# 📡 離線防重複機制測試指南

## 🎯 測試目標

驗證離線時的防重複機制是否正常運作，確保：
1. 新增交易：連續點擊不會產生多筆記錄
2. 編輯交易：連續修改只接受第一次變更
3. 刪除交易：連續刪除只執行一次

---

## 🛠️ 測試環境準備

### 1️⃣ 啟動本地開發伺服器

```bash
# 方法 1：使用 http-server
npx http-server -p 8080

# 方法 2：使用 Python
python -m http.server 8080

# 方法 3：使用 VS Code Live Server
# 右鍵 index.html → Open with Live Server
```

訪問：http://localhost:8080

### 2️⃣ 開啟開發者工具

1. 按 `F12` 開啟 Chrome DevTools
2. 切換到 **Console** 標籤（查看日誌）
3. 切換到 **Network** 標籤（模擬離線）

---

## 🧪 測試場景 1：離線新增交易（已修復）

### 測試步驟

1. **進入離線模式**
   - Network 標籤 → 勾選 `Offline`
   - 或下拉選單選擇 `Offline`
   - 確認頂部出現橙色提示條：「📡 離線模式：操作將排隊，連線後自動同步（請勿重複點擊）」

2. **嘗試新增交易**
   - 點擊右下角「💰 記帳」按鈕
   - 填寫表單（金額：100、項目：測試、日期：今天）
   - **連續快速點擊「✨ 記入日記」按鈕 5 次**

3. **觀察 Console 輸出**
   ```
   ✅ 預期結果：
   📡 離線模式：變更將在重新連線後同步
   ✅ 交易已新增: xxx
   ⚠️ 偵測到重複操作，已忽略
   ⚠️ 偵測到重複操作，已忽略
   ⚠️ 偵測到重複操作，已忽略
   ⚠️ 偵測到重複操作，已忽略
   ```

4. **觀察 UI 行為**
   - ✅ 第一次點擊：按鈕變為「⏳ 處理中...」並禁用
   - ✅ 後續點擊：無任何反應（按鈕已禁用）
   - ✅ 3 秒後：按鈕恢復為「✨ 記入日記」

5. **重新連線**
   - Network 標籤 → 取消勾選 `Offline`
   - 等待 2-3 秒，觀察資料同步

6. **驗證結果**
   - ✅ **只產生 1 筆交易**（而非 5 筆）
   - ✅ 主頁顯示該筆交易
   - ✅ 餘額正確更新

### ❌ 失敗現象（如果防重複機制失效）

- ❌ 產生 5 筆完全相同的交易
- ❌ 餘額錯誤（被計算 5 次）
- ❌ 主頁出現重複記錄

---

## 🧪 測試場景 2：離線編輯交易（v5.8.2 新增）

### 前置準備

1. 確保已有至少一筆交易記錄
2. 記住該筆交易的原始金額（例如：100 元）

### 測試步驟

1. **進入離線模式**（同上）

2. **開啟編輯表單**
   - 點擊任一交易項目
   - 點擊右上角「✏️ 編輯」按鈕

3. **嘗試修改**
   - 將金額改為 200 元
   - **連續快速點擊「💾 保存修改」按鈕 3 次**

4. **觀察 Console 輸出**
   ```
   ✅ 預期結果：
   📡 離線模式：變更將在重新連線後同步
   ✅ 交易已更新: xxx
   ⚠️ 偵測到重複修改操作，已忽略
   ⚠️ 偵測到重複修改操作，已忽略
   ```

5. **重新連線並驗證**
   - Network 標籤 → 取消勾選 `Offline`
   - 等待同步完成
   - ✅ **金額變更為 200 元**（只更新一次）
   - ✅ 餘額正確計算（200 - 100 = +100）

### ❌ 失敗現象（如果防重複機制失效）

- ❌ 產生 3 次更新操作排隊
- ❌ 重新連線後餘額錯誤（可能被多次更新）
- ❌ 最終金額可能不正確

---

## 🧪 測試場景 3：離線刪除交易（v5.8.2 新增）

### 前置準備

1. 確保已有至少一筆交易記錄（金額：150 元）
2. 記住當前餘額

### 測試步驟

1. **進入離線模式**（同上）

2. **嘗試刪除**（假設有刪除按鈕）
   - 長按交易項目 或 點擊刪除圖示
   - 確認刪除對話框
   - **連續點擊「確定」3 次**（如果可能）

3. **觀察 Console 輸出**
   ```
   ✅ 預期結果：
   📡 離線模式：變更將在重新連線後同步
   ✅ 交易已刪除: xxx
   ⚠️ 偵測到重複刪除操作，已忽略
   ⚠️ 偵測到重複刪除操作，已忽略
   ```

4. **重新連線並驗證**
   - Network 標籤 → 取消勾選 `Offline`
   - 等待同步完成
   - ✅ **交易已刪除**（只刪除一次）
   - ✅ 餘額正確扣除（-150 元）

### ❌ 失敗現象（如果防重複機制失效）

- ❌ 餘額被多次扣減（-150 × 3 = -450）
- ❌ 可能觸發錯誤（嘗試刪除不存在的交易）

---

## 🧪 測試場景 4：離線時按鈕狀態驗證

### 測試步驟

1. **進入離線模式**

2. **開啟新增表單**
   - 填寫表單
   - 點擊「✨ 記入日記」

3. **立即觀察按鈕**
   - ✅ 按鈕文字變為「⏳ 處理中...」
   - ✅ 按鈕變灰且無法點擊
   - ✅ 再次點擊無任何反應

4. **等待 3 秒**
   - ✅ 按鈕恢復為「✨ 記入日記」
   - ✅ 按鈕可再次點擊（如果需要）

5. **檢查 30 秒超時**
   - 如果操作卡住（模擬網路異常）
   - 30 秒後按鈕應自動恢復

## 🧪 測試場景 5：離線錯誤提示驗證

### 測試步驟

1. **進入離線模式**

2. **新增交易**

   - 點擊「✨ 記入日記」

3. **觀察提示訊息**
   - ✅ 顯示「📡 離線模式：交易已排隊，將在重新連線後同步」
   - ✅ 表單自動關閉
   - ❌ **不應顯示**「發生錯誤」紅色訊息

## 🔧 除錯技巧

### 1️⃣ 查看操作指紋

在 Console 中執行：
```javascript
// 查看進行中的操作
console.log('進行中的操作:', Array.from(window.DataManager._pendingOperations));
```

### 2️⃣ 模擬慢速網路

Network 標籤 → 選擇 `Slow 3G` 或 `Fast 3G`
- 觀察按鈕禁用時間是否足夠

### 3️⃣ 清除 IndexedDB 快取

```javascript
// 完全重置離線快取
indexedDB.deleteDatabase('firestore/[your-project-id]/[default]');
location.reload();
```

### 4️⃣ 檢查 Firebase 排隊操作

Chrome DevTools → Application → IndexedDB → firestore
- 查看 `mutations` 表（離線排隊的操作）

## 🚀 自動化測試（未來）

可考慮使用 Playwright 或 Cypress 自動化測試：

```javascript
// 範例：Playwright 離線測試
test('離線新增交易防重複', async ({ page, context }) => {
  // 進入離線模式
  await context.setOffline(true);

  // 開啟表單
  await page.click('#btnAddTransaction');
  await page.fill('#amount', '100');

  // 連續點擊 5 次
  for (let i = 0; i < 5; i++) {
    await page.click('[type="submit"]');
  }

  // 恢復線上
  await context.setOffline(false);

  // 等待同步
  await page.waitForTimeout(3000);

  // 驗證只有 1 筆記錄
  const transactions = await page.$$('.timeline__item');
  expect(transactions.length).toBe(1);
});
```
